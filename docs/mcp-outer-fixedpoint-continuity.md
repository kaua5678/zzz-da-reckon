## 2. 根因（第一种不连续：环内选点依赖检出相位）

`pickOuterCycleMember`（`src/composables/resourceCalc/outerCycle.ts`）旧判据：① 失衡自洽度 → ⓪′ 离散自洽度 → ② 时间自洽度（2s 同级）→ ③ 同级取最后一轮。

- 2-环两成员 A→B、B→A 的 ① `|next − stunIn|` 恒相等；② 又常落在 2s 同级容差内 ⇒ 实际由 ③ 决定。
- 「最后一轮」是哪个成员，取决于**环在奇数轮还是偶数轮被检出**。输入微动 → 收敛前的过渡轮数 ±1 → 选到另一个成员 → 规划失衡 0.70 ↔ 1.12。
- 第二个问题：旧实现是**带容差的两两比较**（从后往前），不满足传递性。≥3 成员的环里结果依赖成员在数组中的排列，也就是依赖检出相位。

## 3. 方案（CC-136，已落地）

**逐级筛选（全序）取代两两比较，并在 ③ 之前加 ③′：**

1. ⓪ 零窗成员不参选（不变）。
2. ① 保留 `|next − stunIn|` ≤ 池内最小 + tol.stun 的成员。
3. ⓪′ 再保留 `disc` ≤ 最小 + tol.disc。
4. ② 再保留 `time` ≤ 最小 + tol.time。
5. **③′ 再保留 `stunIn` ≤ 最小 + tol.stun**（输入失衡次数小者）。
6. ③ 仍同级：池内最后一轮。

- **为什么是 `stunIn` 小者**：只看成员自身，与轮次无关；成员之间的 `stunIn` 差得很开（不是 1e-3 级噪声），所以在输入空间里稳定。取「小」= 不高估失衡收益，与 CC-134 floor 同向的保守口径。
- **为什么不用「严格时间差最小」**：它同样与奇偶无关，也能让 `auto-1431-1341-1031` 的留白不变差；但成员间时间差常是 1e-3 级，严格比较等于掷骰子，输入一动就换点，正是本卡要消除的东西。不采纳。
- **为什么改成筛选**：带容差的两两比较不传递（yixuan 语料：0.1685 与 0.1199 同级、0.1199 与 0.2884 不同级），结果随旋转变化；筛选以池内最优为基准，是全序，旋转不变。
- **`+Infinity` 成员**（无结果）：有有限值成员时自然被筛掉；全员 Infinity 时全员保留。与旧语义一致。
- **已知残余**：所有判据都同级的成员（如叶瞬光 C1 两个成员只差 0.06s 时间）仍走 ③ 取最后一轮，结果随旋转变化；但这些成员在所有判据上容差等价，测试按「容差等价」断言。
- **回退点**：`git show 0028eb01:src/composables/resourceCalc/outerCycle.ts` 换回整个函数；同时还原 timeGolden / timeFillRatchet 两份基线和 outerCycle.test.ts 中 yixuan 语料的期望（0 → 1）。

两两比较版 ③′（中间版本）与筛选版在 zd 全部预设上逐位相同（dump / rowsnap DIFF 0），扫描结果也相同；采用筛选版是为了长周期的旋转不变性。

## 5. 第二种不连续：诊断结论（第 161 轮）——物理失衡次数的整数台阶，不是缺陷

### 5.1 逐轮 trace（连续版 trigger.ts，`auto-1201-1361-1211@0`）

方法：在 `runOuterLoop` 里临时加 `globalThis.__outerTrace` 钩子（每轮记 stunIn / rawNext / next / 签名，耗尽后记 lag，退出记选中成员的 `stunPool.stunCount`），探针见 `/home/kaua/calc-arch/trace161-trigcont.txt`（探针源码备份在本沙箱 `w/up/zzTrace161.test.ts`；钩子已移除，`git diff` 干净）。

| w 系数 | 轨迹尾部（stunIn → rawNext → next） | 退出 | 选中成员 | 物理次数 | 总伤 |
|---|---|---|---|---|---|
| 1.045 / 1.05 | 2.2228 →**4**→ 2.9816 → 3 → 2.2049（2-环） | 7 轮 cycle | stunIn 2.2228 | **4** | 29.34M |
| 1.055 / 1.06 | 2.2190 →3→ 2.4083 →**4**→ 2.9287 →3→ 2.2190（3-环，lag=3） | 20 轮 → 长环 | stunIn 2.2190 | **3** | 28.49M |

- 输入几乎相同（2.2228 vs 2.2190），但 w 越过约 1.0525 时，同一输入下的物理次数 `floor(N*)` 从 4 变 3。环结构随之从 2-环变 3-环，这只是伴随现象。
- 两个环都同时含 3 次和 4 次的成员，这正是坑 25「外层 `rawNext × (1 − coverage)` 与池内窗口占比双重折算」让外层映射没有不动点的表现。

### 5.2 全曲线核对：跳变是否都伴随物理次数变化

| 扫描 | 同物理次数的最大相邻跳变 | 物理次数变化处 |
|---|---|---|
| 连续版扳机，旧选点（0028eb01） | **1.869%**（选点伪影） | 0.99%（4→3） |
| 连续版扳机，新选点（CC-136） | **0.047%** | 2.905%（4→3，唯一一处） |
| 当前代码扳机 / 琉音 c6 | 0.009% / 0 | 无 |

**结论（第 161 轮拍板）**：CC-136 之后剩下的唯一大跳变，是物理失衡次数的 floor 台阶（多或少一次失衡，伤害本来就该跳），不是路径依赖。**不修**。

- **验收判据修订**：原判据「扫描曲线相邻跳变 ≤1%」改为「**发布的 `stunPoolResult.stunCount` 不变的相邻点**，总伤跳变 ≤1%」。原判据会把真实的整数效应当缺陷，逼人去抹平它。不采纳原判据。
- **护栏**（CC-137，`30daa4b1`）：`src/composables/__tests__/outerContinuity.test.ts`。琉音 c6 转换系数 1.90..2.10 步长 0.01，共 21 点、约 0.6s，断言同次数相邻对跳变 ≤1%，活性要求比较对 ≥10。反向验证：`outerCycle.ts` 换回 0028eb01 版后红（1.91、2.00 两点在 4 次不变时跳 +5.34%）。
- **回退点**：删掉该测试文件即可，不影响任何数值。

### 5.3 仍然存在的结构问题（不属于连续性，另开卡）

- 规划失衡（外层输入，决定时间分配，这里约 2.22 个窗口）和物理次数（池 `floor(N*)`，决定伤害侧 `allocateAxisWindows(…, Math.round(stunCount))` 和机制行的 `stunCount`，这里 3 或 4 次）是两个数。ENGINE_PIPELINE_GUIDE 第 177 行把它标为「仍双源」，坑 25 标为「已知残差，待裁决」。
- 这会导致时间账按约 2.2 个窗口排，伤害按 3 到 4 个窗口算。这是口径问题，改了会全库动数，不在连续性专项内解决。下一步见队列第 161 轮交接。
