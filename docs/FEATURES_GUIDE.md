# 功能手册：Boss 选择 + 预设队伍对比

> 本手册记录两个"决策层"功能的**操作方式**与**修改入口**，防止遗忘。
> 代码口径以脚本/模块头注释为唯一事实来源，本手册是索引与步骤说明。

## 1. Boss 选择界面（属性配置页顶部）

### 1.1 用户操作

1. 打开「属性配置」页 → 顶部「Boss 选择」卡片。**版本 + 危局期数两级下拉**（一期 = 1 困难 + 3 普通，**都是危局强袭战**；防卫战期默认不收，例外见下）。
2. 每期分三区：
   - **困难 · 危局强袭战**：1 个 Boss，可应用
   - **普通 · 危局强袭战**：当期 3 个 Boss，**同样可应用**（预设覆盖全部危局 Boss 共 23 个 + 老防卫战 Boss 彷徨猎手 1 个 = 24 个；3.3 新增的 40012「以太异体·特里薇亚」（测试服期曾叫「(Test1)僭越者」）与 40014「异构·滞变畸兽」均已正式定名，手录项（体型/弹刀/无敌）里 40012 的体型按 nanoka tag 录、弹刀/无敌待用户核对）
   - **当期 Buff**：3 张可选牌 + 各 Boss 卡上的**关卡固有 buff**（layer_buff 解析）
3. 应用 Boss 时（唯一入口 `composables/bossRoom.ts#applyBossRoom`，CC-342；所有分析器与抽卡规划 / 角色兑现曲线逐房同样走它；数据 = `boss-presets.json` 预设 phase 的 `layerBuffs`）除填充敌人配置外，**自动把该 Boss 当期关卡固有 buff（layer_buff 数值效果）写入全局 Buff 表**（id 前缀 `layer-buff:`，切 Boss 时先清旧）；效果上的特性限定 / 人数分档（`cond`）随行写入，计算时按**当前队伍**判定、换人自动换档（`src/utils/phaseBuff.ts`，CC-341）
3. 一键填充字段：血量 / 失衡值 / 防御 / 等级 / 危局异常系数（`bossAnomalyCoeff`）/ 失衡易伤（`stunVuln`）/ 失衡时间（`stunTime`）/ 三张抗性表 / 战斗时间 180s / 秽盾触发次数 / 能量盾次数 / 无敌时间（预设声明时，如 叶释渊 24s）/ 失衡赠礼（`bossStunGift`，预设 `stunGiftRatio` × 失衡上限，如 亵渎者 30%）。
   **不动的字段**：快支次数（角色侧）。
3.1. **Boss 预设弹刀反推**（声明了 `parryTotal` / `parryNoFollowUpTotal` / `parryDecibelOnlyTotal` 的 Boss）：应用时自动勾选「失衡次数四舍五入」，计算器按当前队伍反推——击破位（首个 stun 特性槽位）**正常弹刀** = 达到四舍五入后的失衡次数目标所需（封顶 `parryTotal`），主C = `parryTotal − 击破位`（主C 已手填则不覆盖）；**不带支援突击的弹刀**（`parryNoFollowUpTotal`，只有轻弹刀倍率行 + 喧响 215、无支援突击行）按**对半分**（击破/主C 各一半、奇数时击破位多 1；2026-09-10 口径，早期「全部归击破位」已废）；**只给喧响的弹刀**（`parryDecibelOnlyTotal`，轻弹刀打小怪无 daze 无支援突击）归击破位，两者均非用户可调；**喧响赠礼**（`decibelGift`）叠加到指定槽位进场喧响。交互栏显示「→ N（含无突击 M / 只喧响 K / 保底反推 +K）」提示，取消勾选即回到手动输入。实现：`src/core/parrySplit.ts` 纯函数 + `useResourceCalc` 外层不动点线程（般岳轴自动补齐同款收敛）。
3.2. **控制技（紫光技）× 反制支援整组替换**（声明了 `counterAssistGroups` 的 Boss，逐组记该组招架段数）：队内有**反制支援**招式的角色（现全库唯一 = 克拉蕾(1611)）时，Boss 卡「反制支援整组替换」默认勾选 → 一组控制技 = 她**一次反制支援**（本体 + 其专属支援突击合成一次动作），**不产弹刀行、不拿弹刀 215 喧响、不参与每次弹刀失衡反推**；取消勾选（或队内无人）→ 整组按「每组 1 次正常弹刀 + 段数−1 次无突击弹刀」并入 3.1 的强制弹刀总数。承接槽位缺省自动（队内第一个有该招式的角色），可在 Boss 卡改为指定槽位。交互栏在「弹刀次数」标签上标「（控制技 N 组已转反制支援）」。两条附带口径（用户 2026-09-12）：**角力 = 一次弹刀同等难度**（`INTERACTION_WEIGHTS.counterAssist = 1.0`，难度明细以「反制支援（角力）N×1」露出，并按承接槽位的截断存活率缩）；**每组直接送 1 层残痕**（琢形原文「重击命中直接添加1层」→ 进克拉蕾残痕/毁伤账本，不吃积蓄效率倍率）。实现：折算 `src/stores/config.ts#bossParryTotals`（computed getter，不改编排层）、产行 `src/core/resource/helpers#buildExecutions`、招式配对表 `src/data/counterAssists.ts`；口径见 `ENGINE_PIPELINE_GUIDE.md` §4 坑 18 末段。**当前无 Boss 录该字段**（通道已建，数据待逐 Boss 手录）。
4. 底部「全部 Boss」折叠：23 个 Boss 按「危局异构（困难）」「危局常规（普通）」两组分组，点 chip 跳转到该 Boss 最新危局期。
5. 已应用 Boss 卡片高亮；「清除已选」撤销高亮（不影响已填数值）。
6. 期数标注：`(测试服)` 期的 buff 是 (Test1)TBD 占位，等正式服重跑 import 自动更新。

### 1.1b 危局环境 Buff（属性配置页右侧「危局环境 Buff」卡，2026-10-26）

用户原话：「属性修改下面也列出了很多队友，似乎用不到了。右边是自创buff，没看到危局期数的环境buff」。
⇒ 本页拆成三块，**各管一件事**：

| 区域 | 内容 | 写不写数值 |
| --- | --- | --- |
| 左上「队友 Buff 配置」 | 全部 29 个角色的队友 Buff（按队伍自动派生，**默认折叠**，折叠标题显示「N 名角色 / M 条，启用 K」） | 用户拨开关/覆盖率 ⇒ 写 `teammateBuffSelections` |
| 右上「危局环境 Buff」（新） | ① 按期数的**当期可选牌**（`selectable_buff`，3 选 1）② 已应用 Boss 的**关卡固有 buff**（`layer_buff`，只读状态） | 选牌 ⇒ 写全局 Buff 表（`period-buff:` 前缀，先清旧）；关卡 buff **不在这里写** |
| 右下「全局 Buff（自创）」 | 用户手填 + 上面两处写入的行 | 用户直改 |

**口径（都在代码里，本节只作索引）**：

- 数据面纯函数 = `src/utils/phaseBuff.ts`：`resolvePhaseEnvironment`（期数 → 环境；layer 段只在「已应用 Boss 且正是本期」出现）/ `selectedPeriodBuffCard`（**「当前选中哪张牌」由全局 Buff 表本身派生**，别页写入或手删行都如实反映）/ `periodBuffRowsOf` / `layerBuffRowsOf`。
- **默认显示哪一期**（2026-10-29）= `src/composables/phaseSelection.ts`：**用户手选 ＞ 已应用 Boss 的房间相位 ＞ 最新一期**（Boss 选择卡同源）。写死「最新一期」会让实战对比页部署的那期整段看不见（归档快照比期视图落后一季时尤其明显：Boss 卡不标「已应用」、本卡报「本期还没有应用 Boss」，而 store 里其实都写好了）。
- 选牌的**唯一写入入口** = `composables/runArchiveDeploy.ts#applyPeriodBuff`（与实战对比部署页同一条通道 ⇒ 两个页面写出的行逐位相同；`cond` 随行带上，由管线按**当前队伍**解析）。
- 关卡固有 buff 的**唯一写入入口** = `composables/bossRoom.ts#applyBossRoom`（点 Boss 卡的「应用此 Boss」时自动写入；本卡只显示「已写入 / 尚未写入」，**不重复写**，否则双计）。
- 页面**不试算**：选牌就写入，不做「自动选最优」（那是 C 档用户口径，`ENGINE_PIPELINE_GUIDE.md` §4 坑 53）。
- 判据：`src/utils/__tests__/phaseEnvironmentBuff.test.ts`（解析口径 + 页面源码锁）+ `src/composables/__tests__/phaseEnvironmentApply.test.ts`（真管线：选中牌进引擎、条件牌按队伍换档、**选牌后队总伤真的变**）+ `src/composables/__tests__/phaseSelection.test.ts`（默认期优先序）+ `src/views/__tests__/archiveDeployUiState.test.ts`（部署后本页停在部署那期，整页 SSR 渲染）。
- 实机：`node scripts/ui-check.mjs --step "tab:属性配置" --step "wait:危局环境 Buff"` ⇒ 点牌后全局 Buff 表出现 `当期·<牌名>` 行、再点「不用」清空；点「应用此 Boss」后关卡段显示「已写入全局 Buff 表」。

### 1.2 数据管道（加新期数/Boss 时）

```bash
node scripts/fetch-nanoka-bosses.mjs [版本号]   # 幂等；缺省读 manifest.zzz.live（正式服）
node scripts/import-nanoka-bosses.mjs           # 生成 public/static/boss-presets.json
```

- **版本口径（2026-10-10 修正）**：缺省取 `manifest.zzz.live`（**正式服**）。此前本脚本是**全仓唯一**取 `zzz.latest` 的抓取脚本，会把预发布构建的 `layer_buff.desc` 抓进来——实测 3.3.x 把库萨里库[识破]写成 20%/层、正式服 3.2 是 10%/层，解析出的 `sharpCritDmg` 差一倍（80 vs 40）。预发布的排期字段名也不同（`live_begin`/`live_end`，正式服用 `begin`/`end`）。要抓测试期须显式传版本号（如 `3.3.12+19476086`），且**只用于占位期**，不要覆盖已上线的正式期。
- **排期字段名归一（2026-10-26 已内置）**：正式服构建（版本号不带 `+`，如 `3.3`）的 `begin`/`end` 就是正式排期，`fetch-nanoka-bosses.mjs` 会自动归一成导入脚本认的 `live_begin`/`live_end`；预发布构建（带 hash）的 `begin`/`end` 是测试服占位日，保持原样（导入侧当作无排期的占位期）。历史坑：不归一 ⇒ 正式期被静默当成「试炼期」，label 只剩版本号、时间轴与归档期相位都排不上。若正式服真出现「未排期」期，它的 `begin` 会是占位值而不是缺失——发现 label 缺日期就先查这一层。
- 原始数据 → `data/raw/bosses/{summary.json, version.json, zh|en/<期数id>.json, monster/<怪物id>.json}`
- 端点与结构见 `scripts/fetch-nanoka-bosses.mjs` 头注释（boss.json / zh|en/boss/<id>.json / zh/monster/<id>.json）
- **期视图**（`phaseViews`，Boss 选择 UI 的数据源）：覆盖全部 50 期（1.4–3.3，**全部为正式排期**；3.3 三期 690481/690491/690501 于 2026-10-23 / 11-06 / 11-20 上线）；每期含 普通 3 Boss（`defense`，可应用）/ 当期 buff（`buffs`）；3.1 起另含 困难 Boss（`criticalAssault`，可应用），1.4–3.0 无困难模式

### 1.4 当期 Buff 解析器（`scripts/phase-buff-parser.mjs`，类型声明 `phase-buff-parser.d.mts`）

- 输入 `selectable_buff` 描述文本 → `{ title, testOnly, effects[], unparsed[] }`
- **口径（用户拍板）**：
  - 失衡易伤 → `stunDmgMultiplierBonus`（与击破角色 buff 同字段，直接加不折算）
  - **锐化伤害 → `sharpDmgBonus`（锋御独立乘区）；贯穿伤害 → `sheerDmgBonus`（命破贯穿增伤区）；锐暴 → `sharpCritDmg`**——三者别混
  - **元素伤害并列（`X属性伤害和Y属性伤害提升N%`、`X/Y`、顿号）→ 每个元素各出一个 `{el}Dmg`**；元素减抗（`无视其N%的X伤害抗性和Y伤害抗性`，含共享值/各自值）→ 每个元素各出 `enemy{El}ResReduction`
  - 特性人数分档（异常 2/3 名、强攻 1 名/2 名）→ `cond.countTier: { specialty, thresholds:[低档人数, 高档人数], values:[低档值, 高档值] }`，计算时按**当前队伍**该特性实际人数选档（`src/utils/phaseBuff.ts#resolvePhaseBuffValue`，在 `resolveSlotPanelBuffInputs` 唯一解析；parser 产出中文特性，经 `specialtyCodeOfLabel` 由 `SPECIALTY_LABEL` 反查成引擎 specialty；CC-341 前只有队伍对比解析，关卡固有 buff 与实战部署页当期牌丢掉条件）
  - 强攻/异常等特性限定 → `cond.specialty`（中文，如「强攻」），队伍无该特性角色则该条不生效
  - 字段补全：`[紊乱]伤害`→`disorderDamageBonus`；`[异放]伤害`→`anomalyReleaseDmgBonus`；`[乱流]伤害`→`turbulenceDamageBonus`；`暴击率`→`critRate`；`喧响值获取效率`→`decibelGainEfficiency`；`能量/闪能获得效率`→`energyGainEfficiency`/`flashEnergyGainEfficiency`；`受到的伤害提升`→`enemyDamageTakenBonus`；`受到的暴击伤害提升`→`enemyCritDmgTakenBonus`；无条件`造成的伤害提升`→`dmgBonus`（`首领敌人/自身` 的 boss 自我增伤跳过）
  - **叠层满覆盖**：`每层[X]/每有1层[X]/每拥有1层[X]/每持有1层[X]…提升Y%` 配 `最多叠加N层/最多累计N层/最多N层/至多可以叠加N层`（或隐式 `施加1层/N层`、`额外施加N层`、`拥有N层[X]时`）→ 按 `Y×N` 录入满叠值（如 彷徨猎手 动摇 7%×5=35%）；`最多叠加N层` 的 selectable buff 按「后，/时，」触发器拆：前段 flat、后段叠层
  - 其余条件效果（施放后持续 X 秒）→ 默认满覆盖，原文保留在 `note`
  - `(Test1)TBD` → `testOnly: true`（**可用，只在标签上标「测试服·可能改动」**；用户 2026-10-31 裁决「占位也可以用，不要拒绝」，
  单一标注实现 = `utils/phaseBuff.ts#phaseBuffCardLabel`）；`unparsed` = 未命中规则表的段落（UI 展示原文）
- 规则表在 `RULES`（正则数组，先命中先得；段落内循环删匹配继续解析；按 `。\n;` 分句）
- **两个数据源都走同一解析器**：`selectable_buff`（当期可选牌 3 张）与 `layer_buff`（当期关卡固有 buff，随 Boss 卡展示/应用）
- 新 buff 文案类型解析不了时：加规则到 `RULES`，或把属性名加进 `TIER_STAT_MAP`（分档）、`STAT_LABELS`（显示名）
- 测试：`src/composables/__tests__/phaseBuffParser.test.ts`（15 条，覆盖分档/限定/多招式/多元素/紊乱异放/受暴伤/叠层满覆盖/测试服）

### 1.5 已知口径

- `attribute_infliction` = 异常条系数万分比（危局 10 → `bossAnomalyCoeff` 1.1）
- 失衡倍率大多 1.5，**名可名/基塔布鲁·滞变畸兽 = 1.25**；失衡时间大多 12s，**复写体·猎血清道夫/滞变畸兽 ≈ 15.02s**

## 3.5 分析工作台（「自由对比」Tab，2026-10-17 工作台化）

**用户操作**：

1. 「模板」下拉选一个起点（内置：角色配置对比 / 命座曲线 / 三人命座边际 / 专武精炼 / Boss 期数 / 配置×命座切片 / 维琳娜命座切片），或直接改参数。

3. 结果卡用「表格 / 长表 / 折线 / 切片 / 3D / 差值」换视角；图例显隐与「当前片」跨视角共用；点切片面板或 3D 折线切当前片；差值视角可选基准系列。长表 = 同一份结果摊平成 `x × 切片 × 系列 → 值`，可导出 CSV（表内滚动，440px 上限）。
4. **从其他页导入**：在队伍对比（加金散点）/ 时间图表 / 血量膨胀跑一次，回工作台在「导入」下拉选最近结果 →「导入」。导入只转换形状、不重新求值（表头显示「导入结果 · 未重新求值」），可直接用表格/长表/折线/差值。
5. 「存为」输入名字 →「保存当前」写 localStorage；「删除」只删 `user:` 预设。
6. **三人命座边际（2026-10-27，用户：「三条线共图，看前期给谁加金、后期给谁加金」）**：在系列区下方选三名队员 →「生成三条线」→ 自动把系列换成三条**同一队形**的整队系列（只变槽 0/1/2，另两人固定 01）、x = 影画、y = 队伍总伤，并打开「锁失衡次数」；点「对比」出图。折线视图默认**三条线都标** `+x.x%`（相邻档；同一 x 上按点的 y 从上到下错开 13px），可取消「三线都标」退化为只标每档最优；图下另有一块 **3×6 逐档矩阵**（行 = 角色，列 = C1..C6，绿 = 该档最赚），「表格」视角也保留全量小字。

**口径**：

- 预设只存**输入**；结果由一次求值产出，切换视角不重算（`composables/freeCompare/views.ts`）。
- 与 x 轴抢同一档位字段的切片不出现/引擎拒绝（`sliceConflicts`）；Boss 期数切片需先选 Boss。
- 用户预设读取时逐条净化，坏条目丢弃；写失败（quota/隐私模式）明确报错（`presets.ts`）。
- 差值 = `(值 − 基准) / |基准| × 100`；基准 0 / 缺失的点断线，不画成 0。
- **三人命座边际 = 局部边际，不是可叠加的路径**：三条线读的是「其余两人停在 01」时各自升一命的收益（C0 三条重合、C6 是三套不同队伍）。看「这一档给谁」看**斜率**（逐档提升%），不是线的高度；买完 A 的 C1 后基线变了，下一金要重看。要序列答案用队伍对比页的贪心加金。
- **锁失衡次数**：`stunLock` 取每个系列**首档自由收敛**的失衡次数并逐档钉死（与 `cinemaUplift` 同口径），C3/C5 不再靠「多打失衡窗」虚增；普通对比默认关（保持既有数字），「三人命座边际」模板默认开。结果逐个系列暴露 `stunLock`，环境行写明锁值；0 窗 = 锁不成，按不锁处理。
- **逐档提升%** = 相邻两档 `(本档 − 上档)/|上档|`（`views.ts#stepGainsOf`）；首档/缺失/零基数 ⇒ 空，不落成 0 或 Infinity。折线默认三线全标（同一 x 垂直避让 13px，标签带主题光晕），可切「只标最优」；图下矩阵给全量 18 格，表格视角小字同源；「越小越好」的指标按下降是否最大判最优。
- 长表是数据层的统一形状（`composables/analysis/dataset.ts`）：行 = x × 切片 × 系列；缺失读数保留 `null`。CSV 只是**可选导出**（原始精度、UTF-8 BOM + CRLF），不是跨页通道；跨页数据在应用内由 `analysis/transfer.ts` 直接传递。
- 跨页适配器：队伍加金（x = 限定金，系列 = 队伍，伤害/血量% 两份）、时间图表（x = 版本/期数，系列 = 主C 的最优队包络）、血量膨胀（x = 期数，系列 = Boss，值 = 版本系数）。专业页跑完经 `analysis/transfer.ts` 发布；工作台 `resultFromDataset` 转成只读结果，`evaluations = 0`。

**修改入口**：`freeCompare/views.ts` / `freeCompare/presets.ts` / `analysis/dataset.ts` / `analysis/transfer.ts` / `data/analysisPresets.ts` / `views/FreeComparePage.vue`；共享图例 = `components/charts/ChartLegend.vue`（已接分析工作台、队伍对比散点/曲线、时间图表强度带、血量膨胀、直伤系数/新角色/菲林/抽卡规划/同槽位对比；筛选状态仍统一在 `useSeriesFilter`）；共享表格 = `components/charts/ChartTable.vue`。

### 4.2 口径（用户拍板 + 实现细节）

- **版本节点** = 卡池期（上半/下半），数据在 `src/data/versionTimeline.ts`（来源：zzz.163.moe/banners + B 站卡池记录；只收 **S 级**，唯一特例 = 潘引壶（1421，A 级贯穿拐，随仪玄 2.0 上实装、0 限定金））。
- **队伤与节点无关**（同队伍 × 同 Boss × 同金数）→ 全组合 C(n,2) 各算一次，每节点最强 = 可达前缀最大值（**精确增量，非贪心/波束**）。
- **搜索排名用「预算感知确定性分配」**（主C优先加金）：排名贴近所选金数，换人时机正确；**最终加金 = 逐金贪婪最优**（影画/音擎本体/精炼每金档全候选取最大提升；非限定槽位也可花 1 金佩戴限定音擎）。函数清单见 §4.3 修改入口。
- **收敛过滤**：失衡外层未收敛（`convergence.outerExit === 'maxIter'`）的队伍伤害虚高（实测青衣系阵容 407%+ vs 收敛 meta 队 105-127%），排除出排名（统计在页头显示）。
- **计算性能口径（实测）**：每次伤害求值 ~30ms、全候选 ~900 对 ≈ 27s ⇒ **默认走策展池轻量档（见 4.1）**；防卡死靠阶段边界 yield（单帧 ~60ms）。两条否决：**贪婪试算区不做 yield**（未还原改动让出会触发 store team watch 重入、扭曲试算，曾致潘引壶测试回归）；**配装不按 agentId 缓存**（队友可用 buff 组随组合变化，缓存使同角色副词条跨队漂移，实测末节点伤害 −13%）。
- **Boss 排期匹配规则**：`phase.begin` 落入 `[node.date, 下一 node.date)` 窗口归该节点（早于首节点丢弃、晚于末节点归末节点），不依赖 version 字符串；同 (节点, Boss, 模式) 去重。数据源 `composables/bossSchedule.ts`，危局期数随导入管道增长后标记自动变全。计算口径不变：整条曲线仍用所选 Boss 一套数值，排期标记只负责定位比较窗口。
- **已知偏差（模型 vs 真实 meta）**：真实演变路径依赖的青衣系队伍目前全部 `maxIter` 未收敛被排除（外层不动点 6 轮内不落稳、伤害漂移虚高，如 仪玄+青衣+橘福福 实测 363% 血量），且收敛队中 仪玄+贯穿拐/击破位 组合排名低于模型偏好组合——时间线排序与真实 meta 尚有差距，待收敛处理与机制精度专项。
- **换人判定（上位/平替）**：换人节点的最优队伤害对比上一节点旧队伤害（同预算下各自最优加金），提升 ≥ `SWAP_UPGRADE_UPLIFT_PCT`（默认 10%，`teamTimeline.ts` 导出常量）→ **上位**，否则 **平替**；单一事实源 `classifySwapUplift`，节点与换人事件 chips/hover 同步显示。
- **实装未进队判定**：当期新实装角色全部不在最优队时，用阶段①参考伤害比较「含新角色最强组合 vs 不含的最强组合」——差距 < 阈值 → 平替·可不抽，≥ 阈值 → 未上位（零额外求值；参考最强含新角色但最优加金后被反超的排名分歧场景不标注）。
- **队伍结构约束**：至多 1 名击破（stun）——真实 meta 无双击破；引擎失衡循环对双击破高估。
- 交互基准：职业基准 roleInteractionBaseline（支援/防护 0 交互，其余弹刀6/闪反10；般岳/星徽·比利/蕾米埃尔按角色默认）+ **快支 0（全角色）/ 连携 1（支援·防护 0）**（用户 2026-10-18）；配装 = 邦布精灵推荐（含词条优化器）；当期可选 Buff 不参与（沿用当前全局 Buff 表）。

### 4.5 抽卡规划器口径（Chart 6，序贯决策优化）

**问题类**：带可用性窗口的多期资本预算（Weingartner 1963 谱系；形式化引 Lorie–Savage 1955 / Weingartner 1963，复杂度引 Karp 1972 / G&J 1979）。**非** Temporal Knapsack（那是窗口内「占用」，我们是窗口内「可购买」、买入后永久持有）。内层每期 3-Boss 不重叠组队 = 三维匹配（经 3DM 归约 NP-难）；带协同的组队 NP-难见 Lappas–Liu–Terzi KDD'09。

**用户口径（2026-08-28 拍板）**：
- 起点预设全做：新号（全限定待抽）/ 成型号（常驻 S + A + 赠送免费可用，0 限定）/ 自选持有。
- **贬值内生**：不设折现参数——老卡分数下降由每期 Boss 血量/抗性数据自然涌现（引擎逐期求值；每房带该期该 Boss 的关卡固有 buff，CC-342）。
- **复刻不建模**：首 UP 窗口 = 唯一购买窗口（最优规划下复刻补抽要求「当时资源受限且复刻期无更强新卡」，两者都罕见）。窗口 = [首 UP 卡池节点日期, 下一个卡池节点日期)（`PlannerCard.windowStart` / `windowEnd`，后者必填、`null` = 其后无已知节点），关窗后本体、专武、满配都不能再买（2026-09-29 前实现无上界，等于永久可买）。
- **只算伤害分**：分数 = `scoreForDamageRatio(伤害/当期Boss血量)`，单房 60000（`data/deadlyAssaultScore.ts`，分段线性 7 段——前段血「值分」多、末段（接近击杀）效率最低，非 `60000×伤害比` 线性；操作分是附加分、与强度无关，已剔除）。
- **音擎 = 1 金但期望更便宜**（10000 vs 15000 菲林）；**每版本免费 25000 菲林**（`PLANNER_FILM_PER_VERSION`），按版本日历发放（`versionFilmGrants`：每跨过一个版本开始日发一份，收入日历 = `plannerVersionStartDates()`；2026-09-29 前误按「期日期变化」每期发一份，每版本约 3 期 ⇒ 收入约 ×3）。没买专武不带专武：持有档逐人映射（不并池灌给主C）；本体档穿固定下位（辅助=高精炼啜泣摇篮，击破=高精炼燃狱齿轮），不逐队搜索。
- 困难（Adversity）不做；音擎金步纳入购买阶梯（本体 15000 → 专武 10000 → 满配 6影画+4精炼）。阶梯是数据表 `pullPlanner.ts` `PURCHASE_LADDER`（每档 = 累计影画 / 精炼 + 文案）：增量成本 `tierCost`、引擎配装 `holdingStateFor`、页面文案 `ppTierLabelOf` 都从它派生，改阶梯只改这张表（但改内容 = 改口径）。

**算法**：
- 外层 beam search：状态 = (持有集 × 银行)，每版本节点展开「买卡（窗口内下一档）/ 攒着（实物期权）」，同节点连买深度 ≤3；去重键 = 持有集 + 银行（1000 菲林量化）+ **累计分**（score 必须进键——否则不同质量前缀被合并丢信息，曾致规划器永远不买卡）。选 beam 不选贪心 = niche 协同（卢西娅单拿弱配命破 C 强）破坏次模性、次模常数因子保证不适用（引用见「学术引用锚点」）；实现 `planPullStrategy`（入口见 §4.3）。
- 内层每期不重叠组队（`pickPeriodAssignment`）：每房一队、9 人不重叠、总分最大的**分支定界精确解**（候选降序，上界 = 已选分 + 剩余各房最高分；凑不出满编时留空房取最大部分解）。原「topM 分桶截断 → ×4 重试 → 逐房贪心」三段式已删（会把唯一可行划分截掉，arena-D 第 365 轮），`assignmentTopM` 参数随之删除。
- 免费人下限：免费池每职业 1 名代表不足 9 人（一期 3 房 × 3 人）时按职业轮转补足（`PLANNER_MIN_FREE_MEMBERS`）；修前只有 8 人，0 持有时第 3 房恒为 0 分，第一张买到的卡白得一整房分。
- **价值归因 = VCG 反事实差分**（`computeCardValuesVcg`）：V(规划 | 卡可购) − V(规划 | 卡禁购)，禁用重规划非禁用。同一引擎同一算法对新号/成型号给同一张卡不同估值（持有集条件化——用户「比利 vs 维琳娜」例的形式化）；命座/专武档同理可定价。**VCG 反事实不等式**：禁用不可能让最优更好（value ≥ 0，测试钉住）。
- **零价值三态必须分开读**（`CardValueVcg.rawGap` / `searchInconsistent`，口径见 `docs/proposals/pull-value-optimization.md` §3.3）：① **确证完全下位** = `value 0` 且 `rawGap` 恰为 0（禁购不改变任何决策）⇒ 有效结论「建议不抽」；② **未持有未抽** = `tierInPlan 0` ⇒ 同上显示 0 但成因不同；③ **搜索不自洽** = `rawGap < 0`（窄 beam 下禁购反而更高分）⇒ 是 **beam 近似告警**，不是卡的属性，页面打 ⚠ 并降调该行。三者都显示 0，`value` 是展示口径（下界 0），`rawGap` 才是自洽性证据。
- **每万菲林的分母 = 该卡实际增量投入**（`CardValueVcg.spentInPlan`，来自 base 轨迹各次购买成本之和；取值走 `cardValuePer10kFilm`）：从本体升专武只算 10000、满配累计 155000（不是按档位硬编码的 1.5/2.5/17 万）。旧口径仅在「满配」与「升档路径」上算错（满配 17 万 vs 实际 15.5 万 = 低估 8.82%；已持有本体升专武按 2.5 万算而实际 1 万 = 低估 60%），从零买 tier1/tier2 时恰好正确。分母 ≤ 0 或搜索不自洽时比值返回 null（显示「—」），不显示成 0。
- 引擎 oracle（`pullPlannerEngine.ts`）：伤害→分数映射 + maxIter 收敛过滤 + 双层缓存（房间 = bossId/phaseId/HP；候选层仅用池内持有档，队级层保留槽序与逐人持有档；未收敛缓存仍排除）；teamTimeline 轻量配装底座；快照/恢复同 Chart 1。**注意**：oracle 是同步的（beam 内不 yield——同 teamTimeline 贪婪区教训），全量规划数分钟，VCG 每卡重规划大量命中缓存。**候选生成**：每个主C（slot0）× 前 `2 × 房间数`（= 6）名队友两两组合；队友按持有档高者在前（买到的限定 S 优先当队友，免费成员保持池序）。6 是「3 房各一队、9 人不重叠」的最低要求（每队 2 名队友）；arena-D 第 362 轮（`3439c9d2`）前是 4，导致第 3 房恒 0 分、买到的卡只能当 slot0。

**学术引用锚点**（FEATURES §4.5 与代码头注释同源）：Weingartner 1963 多期资本预算；Nemhauser–Wolsey–Fisher 1978 / Sviridenko 2004 / Khuller–Moss–Naor 1999 / Krause–Guestrin 2005 次模贪心保证（本问题不适用，说明见上）；Lappas–Liu–Terzi 2009 team formation NP-难；Vickrey 1961 / Clarke 1971 / Groves 1973 边际外部性定价；Charnes–Cooper–Rhodes 1978 DEA（上限口径的方法论出处）；Dixit–Pindyck 1994 / McDonald–Siegel 1986 实物期权（攒菲林 = 持有看涨期权）；Ow & Morton 1988 beam search；Chand–Hsu–Sethi 2002 滚动时域。玩家侧 gacha MDP：Chen & Fang SIGMETRICS'23；保底等待时间 Markov 链：Hou et al. 2026（社区工具 Rettend/zzz-pull-planner 等的分位数把握度思路，v2 风险感知扩展用）。

**已知偏差与边界**：真实 meta 偏差同 §4.2（青衣系 maxIter 排除、模型偏好 vs 真实 meta 排名差）；早期期数数据不全（47 期里 14 期只有 2 Boss、1 期 1 Boss，按实际房间计分）；赠送卡（佩洛伊斯）与 A 级特例（潘引壶）不入购买清单（免费人池）；λ 现实折扣 v1 = 1（纯理论上限口径，效率前沿做回测对照）。

   - **单角色招式明细**：逐招式逐列「实际/期望」比值与标记；**资源列（专属资源 / 残痕积累 / 锐能回复）为秒均**（整招合计 ÷ t），耗能与等效能量互斥合为一列，锋御的锐能回复并进「回能」列（锋御没有 `energy_recovery` 行）；**「秒均伤害」列 = 整招伤害倍率(Lv12) ÷ 有效 t**（比值列已归一化到 ≈100%、读不出 DPS 差异；列头默认按它降序，用于失衡期内挑秒伤最高的招式）；
   - **招式特定偏差清单**：单招式比值偏离本角色列基准 ±5% 以上（连携增强/大招削弱一类设计空间）。

### 5.2 口径

- **模型**：实际录入值(Lv12) = 标准式(const + b×t [+ c×e]) × 等级系数（伤害×2 / 失衡×1.5，引用 `core/skillLevel.ts` 同源常量 `LEVEL1_TO_LEVEL12`）× 稀有度系数（限定S ×1.1 / 常驻S ×1.05，只乘伤害失衡；命破伤害另×0.8）× 角色系数。t = actionTime，e = energyCost 首个非持续项。**特殊技不回能**（原表 3.6t 系笔误，已从标准表删除）。
- **闪能质量 ×1.2**：命破角色的「能」均指闪能。强特消耗闪能（Flash Energy Cost）时，四个耗能利用率系数（伤害 5.55835 / 失衡 4.175 / 喧响 1.909 / 积蓄 4.86）先 ×1.2 再乘闪能量——相同闪能比相同能量多转化 20%。**锚点真斗**：强特「归烬·天坠」耗 80 点闪能（nanoka param 确认，`scripts/patch-move-energy-cost.mjs` 录入），代入后五列比值全部 ≈1.000（测试钉住）；仪玄/般岳在规则之上仍有各自机制偏移，由偏差清单呈现。
- **等效能量（奖励口径，2026-10-24 用户裁决 · 2026-10-31 逐招式复核）**：支援突击的四列常数 ÷ 强特耗能利用率系数（伤害 5.55835 / 失衡 4.175 / 喧响 1.909 / 积蓄 4.86）= **20.03 / 20.00 / 19.96 / 20.00** ⇒ 支援突击公式 ≡ **强特公式在 20 点等效能量处**——弹刀后那条支援突击是「送 20 点等效能量」的奖励招式。反制支援**本体 = @40（招族价，三家反解一致）**：克拉蕾 1611028 / 挽昼 1601204 / 知更鸟 1661017 的失衡/喧响/积蓄三列都落在 40.0±0.06。反制支援**专属追击 = 招式级事实、不按招族定价**（`COUNTER_ASSIST_FOLLOW_UP_EQUIVALENT_ENERGY`）：克拉蕾 1611030 琢形 = @80（基线 + 60，两行合计 120），但**挽昼 1601205 灯塔 = @20（就是普通支援突击基线本身、零奖励）**——2026-10-31 用户提问「灯塔说送了很多等效能量、各项数值却都低」触发复核：套 @80 会把她的四列统一压到 0.51~0.59 的假象，按 @20 评估则失衡/喧响/积蓄 1.000、伤害 = 她的直伤系数 1.091（四列独立同证）。等效能量是策划调倍率时的记账单位、**不是玩家花的能量**（真实耗能才走 `energy`/energyCost）；命破的「能」是闪能，同样四个系数再 ×1.2（`FLASH_ENERGY_QUALITY`）；锋御的锐能无关（只是开状态的计时器资源，不产生奖励倍率）。单一事实源 = `standardMultiplierTable#EX_ENERGY_CONVERSION / EQUIVALENT_ENERGY`；**支援突击实录常数原样保留**（`ASSIST_FOLLOW_UP_FORMULA`，一字不改——它是社区表原值，用 `20×系数` 重算会让伤害常数 111.35→111.167、全库直伤系数集体漂移），反制系由 `counterAssistFormula(基线, 奖励能量)` 在其上叠加折算量。
- **资源列（无标准式的专属资源行，2026-10-29 用户口径）**：登记表 = `standardMultiplierTable#RESOURCE_ROW_IDS`，三项都**没有标准式** ⇒ `ratio = null`、不进纵向聚合与偏差清单，展示单位是**秒均**（整招合计 ÷ t）——总数值随招式长短变化（星徽·比利「动力压制」0.2s/4 点 = 20/s 与「抓地轮毂」2.1s/8.4 点 = 4/s 整招合计只差 2 倍、秒均差 5 倍），用户原话「专属资源该用秒均数据而不是总数据」。三项：① 专属资源 `attack_data_0`（青衣闪络电压 / 星徽·比利决意 / 猫又呼噜…）② **残痕积累 `gash_buildup`**（锋御 600 点 = 1 层；用户 2026-10-29 报「锋御的残痕积累没写」——此前整列缺失）③ **锐能回复 `sharpness_gain`**（锋御的「能」= 锐能，catalog 没有 `energy_recovery` 行 ⇒ 并进明细表「回能」列显示，用户原话「回能也可以把锋御角色的回复锐能加进去」）。耗能（真耗能：普通能量/闪能/锐能）与等效能量（奖励记账单位）**互斥**，合为一列。**「秒均伤害」列同源**：`MoveCellEval.perSecond`（整招伤害倍率 ÷ 有效 t，t 含 `MOVE_TYPE_TIME_SCALE` 缩放）——失衡期内挑秒伤最高招式的依据，判据在 `multiplierCoefficients.test.ts::秒均直伤倍率`。单元格契约的判据在 `multiplierCoefficients.test.ts::角色专属资源行`。
- **纵向系数聚合口径**：只取干净类型（排除强化特殊技、轻/重招架、**反制支援系**、未分类），列内取中位数抗脏行；中位数落进 **±0.5% 噪声带**的抹成 100%（原始数据从小数位截断，用户口径「中位数偏差不多就算成 1」；只影响系数展示与偏差基准，不改录入值）。**支援突击为锚点**（通常不随角色变化），其伤害列比值即「版本直伤系数」——反制支援本体 1611028 与琢形 1611030 自 2026-10-24 起是独立招式类型（`data/counterAssists.ts` 登记表定点分类，不按名字扫），分类上就不进锚点样本。支援突击的「#N」分段按同套合并（前缀项只计一次，苍角实证三列 ≈1.000）；般岳「冲霄」经 `MOVE_TYPE_OVERRIDES` 定点改判为闪避反击公式（金身格挡后招式，锚点由「昂霄」承担，比值 ≈1.000）。
- **已验证钉子（测试钉住）**：爱丽丝失衡 90%、伊德海莉（章鱼）喧响 ~49%、耀嘉音/琉音回能 50%、叶瞬光失衡 50%+喧响 80%、蕾米埃尔喧响 50%、悠真积蓄 70%、薇薇安积蓄 80%、南宫羽喧响 90%、凯撒/月城柳失衡 ~91%；可琳 A 级基线五列 ≈100%；秽盾列全角色无偏差；般岳「山摇」闪能 ×1.2 手算比值；般岳/苍角直伤锚点 ≈1。

## 6. 位置对比（「位置对比」Tab）

  - 该号位角色职业 ∈ `attack / anomaly / rupture`（主C视角）：自身总伤拆成 直伤 / 异放 / 紊乱 / 其他异常 四块（其余异常 = 灼烧/感电/侵蚀/风化/强击/碎冰/乱流/耀变/极性强击/极性紊乱/畏缩DOT 等），另给 失衡值/占比 与 积蓄量/占比。

## 7. 实战对比（「实战对比」Tab）

### 7.4 口径

- 配装 = 计算器默认理想（推荐驱动盘 + 推荐主词条 + **模板默认副词条** + 技能全满，作为理论**上界**）；卡片「配装最优」按钮 = 显式按本队重算 4/5/6 主词条与副词条（逐槽爬山 = 近似最优，**缺省不跑**，见 `composables/loadoutOptimizer.ts`）；不从视频提取真实配装。
- 交互基准 = 不预设弹刀——弹刀由「失衡次数四舍五入（Boss 预设反推）」运行时反推（2026-10-23 删掉了并行的「保底4喧响」通道）；闪反按职业基准（roleInteractionBaseline：支援/防护 0 交互，其余 10）；**快支 0（全角色）/ 连携 1（支援·防护 0）**（用户 2026-10-18）；轴模式由轴内连携块反推覆盖。
- Boss = 期相位血量（**危局总血量 = nanoka 单管血量 `mo.stats.hp` × 管数：普通 8.74 / 困难 15.8**；`mo.stats.hp` 已含 4 号血量成长曲线 70 级 × 版本系数）+ 关卡固有 layer_buff 自动应用；当期可选牌（3 选 1）**不自动应用**（归档未记录玩家选择）。
- 仅危局强袭（Deadly Assault*，含 Adversity），防卫战/歼灭排除。
- 比对口径：伤害/血量%（击杀线 100%）+ **伤害分**（`data/deadlyAssaultScore.ts` 分段线性，普通/困难两套曲线，按 run.mode 自动选；操作分已剔除）vs 实战 score/bossKilled/time；归档 65000 = 60000 伤害分 + 5000 操作分，击杀即伤害分 60000。差异 = 配装差 + 建模误差，靠理想配装上界夹逼隔离。

### 7.6b 副词条收益曲线（2026-10-21）

**入口**：收益分析页底部「副词条收益曲线（第 x 步的边际提升）」卡 → 选槽位 → 点「计算曲线」。

**它回答什么**：自动副词条配比为什么是 `{精通 20, 大攻击 12}` 而不是别的分法。

- **x 轴 = 该词条的第 x 步**（一步 = 一次副词条强化；其余词条留在自动配比给的值）；
- **y 轴 = 这一步相对「自动配比后」队伍总伤的边际提升**（分母固定 = 基线总伤，故各曲线可直接比高低）；
- **虚线 = 配比门槛** = 入选词条**末步**边际的最小值。曲线在虚线以下 ⇒ 这一步不值、配比没选它；
- **空心圆点 = 自动配比实际给出的步数**（实心小点 = 采样点）；
- **表格「判定」列**四态：入选 / 边际不足·舍弃（首步 < 门槛，配比按边际正确舍弃）/ 够格但未入选（首步 ≥ 门槛却没被采纳 ⇒ 值得看一眼）/ 无收益（整条恒 0，如生存词条）。

**默认可见集** = 模板词条 ∪ 已入选词条 ∪ 首步最高的 2 条非模板词条（用户口径「我选择显示了大攻击、精通、小穿透，看到不同区间的收益高低关系」）；其余点图例展开，纵轴按可见曲线缩放（`seriesFilter` 口径 ②）。词条名用中文简称（`data/substatLabels.ts`：大攻击 / 精通 / 小穿透…），不用 catalog 的英文名。

**成本与交互**：一次求值 50–75ms/点；10 个词条 × 单词条上限 20 步，恒 0 词条在连续 2 步后止损（`ZERO_GAIN_RUN`），实测整张图 3–10s。故**显式按钮触发**、跑在独立场景上（采样不动你的配装，也不让页面为中间态重算）；配装变了卡片顶部会提示「重算曲线」。

**为什么不做成自动**：按 `ENGINE_PIPELINE_GUIDE.md` §4 坑 53 的分档，这属于 **B 档（估算级）**——它的结论依赖「其余词条不动」这个简化口径，不是不变量；自动跑会让用户以为它是权威分配。

### 7.6c 副词条评分（单人）与两套盘子对比（2026-10-23）

**入口**：收益分析页「副词条评分」卡 → 选角色 → 点「计算评分」；下方「两套盘子对比」存 A / 存 B → 对比。

**用户口径**：「副词条评分该算单人的，因为有人要算他对一个角色的词条养成进度。也有人要比较两套盘子谁的伤害高」。

**① 单人评分（主用法）**

- **基线 = 只把该角色的副词条清零**，队友词条一个都不动 ⇒ 回答「这个角色这套词条值多少」；
- **两个口径一起给**：**该角色自身伤害**（看词条养成进度）与**全队伤害**（看这个角色值不值）。
  两个数各自独立闭合（Σ 逐条 ≡ 各自评分），不是把一个数换算成另一个；
- **逐条贡献 = 精确 Shapley**：Σ 逐条 ≡ 评分、逐位相等 ⇒ 拆解可直接相加看账；
- **为什么不用单项边际**（"只删这一条"）：词条之间互相放大（攻击×暴击×暴伤、穿透的非线性防御区），
  单项边际加起来**超过**总增益 —— 实测 3 异常队 leave-one-out 和 87.82% vs 真值 77.81%；
  顺序边际虽可加，但换遍历顺序就是另一组数，不可解释；
- **成本**：单人只有 2~4 条词条 ⇒ 2^n−1 = 3~15 次求值（约 0.1–0.4s），几毫秒级体验；
  全队口径（6~9 条词条）要 63~511 次（1~10s），故**默认按单人算**；
- **轴态**：词条可能改变失衡次数（如琉音暴击率抬冲击力），跨轴态时卡片提示——那是"多出一次失衡"的
  整窗易伤差，不是词条本身的价值。

**② 两套盘子对比**

- A / B 各是一份**完整**驱动盘配置（4件套 + 2件套 + 4/5/6 主词条 + 副词条），
  分别装到选中角色上求值 ⇒ 其它角色一字不动，差异只来自这一槽；
- 给「全队 / 该角色自身」两个差值，并**逐项列出差异**（套装 / 主词条 / 副词条），
  以及两套的副词条总步数；
- 成本固定 2 次求值（瞬时）。A vs A 恒 0、差异表为空（判据里有反空洞断言）。

**③ 分数换算（A 打了 x 分，换成 B 的伤害会打多少，2026-10-27）**

用户原话：「根据伤害之比，填写普通还是绝境（血量曲线不同），再填写其中一个伤害 A 或者 B 的分数，可以算出另一个配置的分数。
让用户知道，如果你是 A 配置打了 x 分，换成 b 配置的伤害，其他都不变，你会打多少分。」

- **输入**：曲线（普通 / 绝境 / 木桩——木桩没有操作分，用户 2026-10-28）、伤害口径（全队 / 该角色自身）、
  已知哪一套（A / B）、那一套的**总分**、其中操作分（木桩无此项）；
- **只填总分**（用户 2026-10-28：「用户看到的分数就是总分，他来填总分，我们默认操作分 5000（也能改），
  然后 −5000 自动算出伤害分」）：玩家在游戏里看到的 65000 是**总分**，所以主输入框是总分，
  操作分缺省 **5000**（可改，改过的值沿用）；`splitTotalScore` 扣出伤害分后才进曲线，
  输入框下实时显示「总分 − 操作分 = 伤害分」；
- **输出**：另一套的分数 + 差值 + 两边的「伤害/血量%」，并给出「伤害分 + 操作分」的拆分（木桩只有伤害分）；
- **为什么不能拿分数直接乘伤害比**：伤害分曲线 **分段线性且非线性**（大攻击 +10% 落在不同血段换到的分不同）。
  必须 **反解 A 的血量比例 → × 伤害之比 → 正算回分数**（`data/deadlyAssaultScore.ts#damageRatioForScore` /
  `#scoreForDamageRatioOfRatio`）。实测：36000 分 + 10% 伤害 = 38205 分，**不是** 39600（判据里钉了这条反例）；
- **伤害之比取「锁失衡」那一份读数**（与上面两行同源）：不含「多打一次失衡」的离散跳变，否则结论会被一次失衡带偏；
- **操作分**（0~5000）原样加回、**不进曲线**（打得快会改变操作分，这里不臆测，故只做加减）；
- **钳制如实报**：打死（伤害分封顶 60000）或血量 0 时显示警示，不假装比例还线性；
- 判据：`composables/__tests__/substatScoreConvert.test.ts`（非线性 / A↔B 对称 / 比值 1 恒等 / 操作分不进曲线 /

### 7.6d 伤害影响与响应面分析（变量表与分组，2026-10-25）

**入口**：收益分析页「伤害影响与响应面分析」卡 → 2D（单变量敏感度曲线）/ 3D（双变量响应面）。

**变量从哪来**：`src/core/impactVars.ts`（静态表：Boss / 环境 / 抗性 / 平A时间权重）+ `composables/impactVariables.ts`（动态：角色机制设置、柏妮思异放占比）。
下拉按 **Boss 数值 / 战斗环境 / 抗性 / 队伍时间分配 / 角色机制设置** 分组；分组只影响呈现，采样仍在各变量自己的 `defaultRange` 上等距取点。

**收录判据 = 字段在求值链上有消费者**（不是「面板里有这一栏」）：
- 收录的每条变量都由 `impactVariableEffects.test.ts` ① 两端采样证明会改变结果（伤害类看队伍总伤、`*失衡抗性` 看失衡池总失衡值）；
- **不收** `hp` / `level` / `bodySize`：hp 只被消费端做「伤害 ÷ 血量」派生、等级系数是常量 `LEVEL_COEFF_60`、体型是分类值 ⇒ 同测试 ② 反向断言（将来有了消费者会红）。
- **加一条变量** = 在 core 表加一行（`enemyNumberVar` / `resistanceVar` / `timeWeightVar` 三个构造器复用读写口径，别手写 read/write）；分组由表的连续排列决定；3D 快捷对比对加在 `composables/impactVariables.ts#IMPACT_PRESET_PAIRS`（测试 ④ 断言 id 真在表里）。

**采样区间必须覆盖真实域**：测试 ③ 从 `boss-presets.json` 的 159 个相位取实际取值，断言落在 `defaultRange` 内（旧 `Boss 失衡值阈值` 区间 [500, 8000] 对真实域 14068~23277 整段在域外，已改 [8000, 25000]）。

**两种观测口径的区别**：`*失衡抗性` 先改攒条，失衡次数取整后总伤可能不变（实测 physical 队失衡值 57683→55053 而伤害不动）⇒ 它归「失衡池」通道，不要因为总伤没变就以为变量没生效。

### 9.2 用户记忆（「用户记忆」页签）

用户口径（2026-10-09）：「每个用户有自己的记忆文件，比如他觉得他的某个角色玩的不好，就把这个角色某些数值

| 概念 | 口径 |
| --- | --- |
| **记忆模式开关** | 打开 ⇒ 改动**立刻**计入记忆并实时落 localStorage；关闭 ⇒ 改动**不计入**（判据：记忆文件逐字节不变）|
| **自动分层** | 队友 buff **开关** → **队伍记忆**（勾选随队伍组成变）；**覆盖率** → **全局记忆**（操作手感，换队仍适用）。两侧都可手动改判 |

| **恢复出厂值** | 清空全部记忆、一切回到开发者标准值（= 加载一份「全为不修改」的记忆文件），**执行前自动备份**当前记忆成一个具名记忆 |
| **加载记忆文件** | 从**具名记忆槽**（本地多份）或**导入的 JSON 文件**恢复某一份。⚠ 与「恢复出厂值」是**两个独立按钮**、两件事 |
| **导出/导入** | 导出写 JSON 文件；导入解析失败**可见报错**（不静默回落——静默会让用户以为记忆丢了）|

## 10. 更新日志（顶栏图标按钮 → 弹层，2026-10-12 新功能）

入口：**顶栏右侧「报纸」图标**（与「设置」「主题切换」并列）。用户口径（2026-10-12）：
「写个更新日志展示」+ 选定形态「页头图标按钮 → 弹层」、来源「git 提交自动生成」。

### 10.1 用户操作

- **搜索**：按**摘要 / 类型名 / commit hash** 过滤（hash 大小写不敏感）——常有人拿着一个 commit 号来问「这条是什么」。
- **筛选**：`功能 / 修复 / 重构 / 文档 / 其他` 贴片，可点两次取消（点选中的那个 = 回到全部）。
  贴片上的**数字随搜索词变化**（否则会出现「按钮说 333 条、点进去只有 12 条」）。
- **分组**：按**作者日期**倒序，每天一条日期条 + 当天提交；被筛空的日期**不显示**（不留「0 条」的空日期）。
- **刷新**：**强制重取**（带 cache-buster，绕开部署态 `max-age=600` 的浏览器/边缘缓存）+ 页脚显示
  「最近取数 HH:MM:SS」作为「点过了」的反馈。⚠ 刷新**只能拿到已发布的产物**——日志随 `push → 部署`
  更新，本地新提交没部署之前，刷新多少次内容都不会变。

### 10.2 数据管道（唯一事实源 = git 历史）

```bash
npm run gen:changelog     # node scripts/gen-changelog.mjs —— 重新生成 public/static/changelog.json
npm run changelog:check   # node scripts/gen-changelog.mjs --check —— CI 完整性校验
```

| 要改什么 | 改哪里 |
| --- | --- |
| 摘要怎么解析（type/scope/未识别怎么办） | `scripts/lib/changelog.mjs#parseCommitSubject`（正则与「大小写敏感」的判据理由在该文件头注释） |
| 类型 → 中文名 / 分类 / 排序 | `scripts/lib/changelog.mjs#TYPE_META`（**唯一**类型表，UI 的贴片直接读产物里的 `kinds`，不另抄一份） |
| 哪些提交进日志 | `gen-changelog.mjs` 的 git 参数（现为 `--no-merges`；**保留全部提交含 docs 与任务编号标题**，分类交给 `kind`，不删） |
| 日期口径 | `%ad --date=short`（**作者**日期）——用 committer 日期会让 rebase/cherry-pick 把一批老提交堆到最新一天（实测 100 条 at≠ct） |
| UI 文案 / 行高 / 配色 | `src/components/ChangelogDialog.vue`（逻辑在 `src/composables/changelogView.ts`，纯函数有单测） |

### 10.3 口径与坑

- **按需加载**：400 KB / 2460 条的历史数据**不进启动门**（`calculatorStartup` 只加载计算必需依赖），
  打开弹层才 fetch（`stores/catalog.ts#loadChangelog`）。加载失败**只落在弹层里**，不阻断计算。
- ⚠ **产物比它自己所在的那次提交落后一代**（源码与产物同提交进来 ⇒ 产物不含「本提交」）⇒
  `changelog:check` 校验的是**完整性**（产物每条都在 git 里且逐字段相同 + 落后 ≤ `TOLERANCE` 条），
  **不是**逐字等于刚生成的结果。改回逐字比对会让每次提交后 CI 必红（口径与理由见脚本头注释）。
- ⚠ **CI 必须 `fetch-depth: 0`**：默认浅克隆只有 1 个提交，校验会因「产物引用了不存在的历史」而假红。
- ★ **发布链路（2026-10-22，用户实测「线上还是老版本」）**：`changelog.json` 此前是**纯人手提交的产物**
  （忘了跑 `gen:changelog` 就静止），实测落后过 **177 条**；线上站点停在最后一次部署（`86eaa5f0`，
  10-13）——本地领先 153 个未 push 的提交，所以用户看到的就是「网站还是老版本」。
  现在 `.github/workflows/deploy-pages.yml` 在**部署时**用全历史重新生成（checkout 加 `fetch-depth: 0`），
  并断言「产物 head == 本次部署提交 且 条数 ≥ 100」——漏了全历史会红，而不是把残缺站发出去。
  ⇒ **口径：更新日志只随 push + 部署更新；「刷新」是缓存击穿，不是重新发布**（@fact
  `ui:changelog/发布时机`，锚 `stores/catalog.ts#loadChangelog`）。
- ⚠ **标题里的 `NaN` / `Infinity` 在产物侧规范化成「非数 / ∞」**：`ui-check` 的 DOM 体检把页面文本里
  这两个词判为「未格式化数值」并让实机点通失败（r716 闸门）。闸门**不能放松**（它同时防着真的数值外露），
  故换的是文本措辞（`sanitizeSummary`）—— 实测本仓库真有两提交标题在讲这两个词。
- 入口按钮的无障碍名是 `aria-label="更新日志"`：`ui-check` 的 `performClick` 按**可见文本或
  aria-label/title** 命中，纯图标按钮没有文本节点（该修复先例见 `ui-check-runtime.mjs` 里齿轮「设置」那条注释）。

判据：`src/scripts/__tests__/changelog.test.ts`（解析/分类/规范化/产物对账，29 条）、
`src/composables/__tests__/changelogView.test.ts`（筛选/搜索/空日期/计数/页脚自证，20 条）、
`src/stores/__tests__/changelogLoad.test.ts`（产物契约/store 接线/刷新击穿/入口扫描器，16 条）、
`src/scripts/__tests__/deployChangelog.test.ts`（部署链路：全历史 checkout / 部署时重生成 / head 断言，4 条）。
