# 角色特殊机制理解与实现方法

> 给后续 AI 记录角色特殊机制时的统一思路，目标是减少来回确认、把机制落到可计算的数据和代码。

## 1. 理解机制的顺序

1. 先读 `passive`（核心被动 + 额外能力），确认机制主干：伤害形态、资源、状态、触发条件。
2. 再读 `skill` 描述，找到具体招式名和伤害段，和倍率表 moveId 对应。
3. 最后读 `talent`（命座），区分哪些是本体机制、哪些是命座增强。
4. 对每条机制问三个问题：
   - 来源：什么动作/事件产生它？
   - 消耗：什么动作/事件消耗它？
   - 收益：消耗后换来什么（伤害、状态、额外动作）？

## 2. 机制分类

- 资源（resource）：有存量、有获取、有消耗，例如洛克茜风能、克拉蕾锐能。
- 状态（state/stack）：叠加在敌人或自身上的层数，例如克拉蕾残痕（敌人 3 层）、风眼（场上对象）。
- 事件（event）：不占普通招式行、由动作触发的额外伤害，例如毁伤、风眼毁坏、小旋风秒伤。
- 转模（attribute conversion）：由某个属性阈值/步长换另一个属性，例如洛克茜初始防御 → 攻击/冲击。
- 覆盖率：没有专门说明时默认 100%（结果页有覆盖率调整接口）。

## 3. 落库路径

1. 机制描述先写进 `src/specs/agents/<id>.json` 的 `resources` / `events` / `attributeConversions` / `notes`。
2. 能在通用解释器表达的用 spec 数据；需要按动作轴计算的在 `src/mechanics/agents/<id>.ts` 实现并注册。
3. 可确认数值写进 `verifications`，变成 golden test。
4. 猜测机制先落库并标 `[猜测·置信度]`（见 `docs/GUESSING_GUIDE.md`），未确认的保持 `not_described_not_implemented` 或 `implemented_approximation`，在 notes 里写清缺口与待核对点。

## 3.1 事件 → 倍率表映射

倍率表里少部分行不是“一个招式对应一行”，而是被多个事件按关系复用。用事件来定义“实际招式调用哪一行倍率”：

- `executionKind: "execution"`：该事件会生成实际招式执行，进入伤害池。
- `carrierMoveId` + `multiplierRowId`：指定调用倍率表的哪一行（默认 `damage`）。
- `multiplierRatio`：复用时的缩放系数，例如风炮 = 起风倍率 × 0.3 + 风炮爆炸倍率。
- `countField`：次数由机制模块通过 `counts` 上下文传入，支持非内置 countSource。
- `overrides`：模块可对事件动态覆盖倍率（例如葬血强袭按消耗个人资源每点 +6.5%）。

实现位于 `src/specs/mechanics.ts` 的 `buildSpecEventExecutions`，洛克茜/克拉蕾模块已用它生成风炮、风眼、毁伤等实际招式执行。

## 4. 已实现机制的角色

### 丽娜（1211）

- 核心被动：队伍中其他角色获得 `min(30, 丽娜局外穿透率 × 25% + 12%)` 穿透率；明确排除丽娜本人。影画1通过增益修饰器将结果提升至 130%。
- 额外能力：同属性或同阵营队友触发；感电持续时间 +3 秒，全队电伤 +10% 按敌人感电覆盖率近似。
- 终结技回能：其他角色各 +10 能量，下一位换入额外 +20；三人队按下一位 30、上一位 10，两人队另一人 30。
- 影画2：自身伤害 +15%，按 12 秒持续 / 18 秒冷却折为 2/3 覆盖；影画4 双邦布在外回能 +0.5/s、影画6 全队电伤 +15% 均支持覆盖率调节。
- [一尘不染]（邦布攻击）：发动强化特殊技 / 连携技 / 终结技后进入 [一尘不染]，每次持续 13 秒；期间杜苏拉或安娜塔莎每 2.5 秒攻击 1 次（按 [普通攻击：晨间清扫] 三段倍率之和计，**晨间按物理伤害**），每次攻击获得 1 层 [惊吓]；[惊吓] 满 6 层后下一次攻击改为 [普通攻击：午夜清扫]（**午夜按电属性伤害**，即每 7 次攻击转化 1 次）。总 buff 时长按战斗总时长钳制；后台自动、不占前台时间。元素覆盖经 resolveExecutionDamage 钩子实现（倍率表内该两招标注为电）。
- 未建模：两只邦布与敌人感电的逐秒状态，统一以整局覆盖率表达；[惊吓] 层数跨窗口是否保留按整局累计近似。

### 洛克茜（1621）

- 风能：每消耗 30 能量 +1；3 只是存量上限，不限制整局总消耗，默认获得多少消耗多少。
- 风炮：起风/乘风结束时若存在风能，自动释放风炮，消耗全部风能，造成 0.3 × 起风倍率 + 爆炸倍率。
- 风眼：风炮消耗风能后生成 1 个风眼（30 秒）；旋风锤命中会引爆并生成追踪小旋风；风眼被摧毁时造成一次范围伤害。
- 小旋风/风眼伤害分别按 `1621006`、`1621021` 倍率（按秒/次）录入。

### 克拉蕾（1611）

- 残痕（敌人层数）：队友为当前操作角色时每秒积累 3% 残痕值，1 层 = 33.33%；全局资源计算不关心单次满值。
- 残痕消耗：斩金断铁 / 葬血强袭命中残痕敌人时消耗 1 层，触发毁伤追加伤害。
- 毁伤收益：全队触发毁伤时克拉蕾 +1 个人资源；二命额外 +0.25 锐能。
- 葬血强袭：发动时消耗所有个人资源，每消耗 1 点使葬血强袭（1611014）与毁伤伤害倍率（1611015）伤害提升 6.5%，发动期间无敌。
- 锐能：EX 秘血铸锋消耗 60 锐能；进入猩红铭刻后血华誓招式暴击率 +35%、伤害 +25%。
- 锋芒毕露：穿透率 +20%、造成失衡值 +10%，通过毁伤进入后首次切换至击破/锋御队友时复制给该队友（队友拐，默认 1 名满覆盖）。
- 倍率表：`1611014` 是强化特殊技·葬血强袭（1711.2%/838%），`1611015` 是毁伤伤害倍率（1232%）。
- 锐暴伤害：基础固定 120%，克拉蕾核心突破额外 +30%，最终 `sharpCritDmg = 150%`。

### 柏妮思（1171）

- 燃点：进场 100，每消耗 1 能量 +1.4，终结技 +50；单次存量上限不限制整局消耗。
- 余烬：每 8 燃点触发 1 次，触发次数 = min(燃点预算, 总时长 / CD)，由资源池自动计算，资源利用率页不提供用户调整。
- 单次余烬：350% 攻击力火伤 + 60 基础火属性异常积蓄；1 命后伤害 +100% 攻击力（450%）、余烬积蓄效率 +25%（效率区，基础积蓄仍为 60），积蓄加成只对余烬生效。
- 精通加成：每 10 点异常精通使余烬伤害 +1%，上限 30%。
- 命座：C1 开局燃点 100→140；C2 全队穿透 +20%（走队友 Buff 自动生效）；C4 强化特殊技/支援攻击/余烬暴击率 +30%、双喷上限 2.274s→3.274s；C6 双喷每 0.5s 触发一次固定 60% 特殊余烬（不耗燃点，不吃 1命/精通加成）、双份/特殊余烬/灼烧无视 25% 火抗、火焰冲击命中灼烧敌人额外结算一次灼烧，倍率 = 灼烧基础 50% × 1800% = 900%（按异常公式，同一目标 20s 一次）。
- 特殊余烬次数目前按“双喷持续+爆炸时长 / 0.5s 向上取整 × 双喷次数”近似；灼烧迸发次数按 min(双喷次数, floor(总时长/20s) - 1) 近似，180s 时上限 8 次。
- C6 特殊余烬与灼烧迸发注册为双喷 `1171012` 的伴随事件，失衡轴里使用双喷强特时跟随该动作的轴内易伤。
- 搅拌式：`Basic Attack: Mixed Flame Blend #1 × 0.5 + #2` 融合为一次支援攻击，单次消耗 20 点燃点并附带一次不耗燃点的余烬；次数默认按余烬预算后的溢出燃点取上限，资源利用率页可手动调低。
- 流火计数：普通余烬 +1，搅拌式附带余烬 +2；12 点计数 = 1 点流火。消耗 1 点流火发动灼热抛接法（`1171026`，400.1%）并触发一次 300% 异放；计数利用率默认 100%，可调低模拟浪费。
- 灼热抛接法的异放按异常公式结算，基础属性提供者按异常覆盖时间占比分配：所有元素（含风）都默认按实际覆盖秒数比例分配次数，资源利用率页可按元素调整比例；结算面板统一用柏妮思。风异常只是不被紊乱覆盖，不等于覆盖率必满。

### 蕾米埃尔（1581）

- 耀变次数不是用户设置项，由队友异常触发池自动结算：虚耀池 = 非蕾米槽位异常触发数；支援技按池数、终结技按 `floor(池数 / 3) × 3`、普攻按 `池数 × 6命倍率`。
- 资源利用率页只保留“蕾米 Q 耀变分配”来选 Q 批次由哪名队友提供，不再提供“耀变触发次数”输入。

### 雅（1091）

- **烈霜（frostfire）是独立元素**：独立积蓄槽、独立异常触发、20s 持续时间、600/75 紊乱倍率、冰属性增伤键（`iceDmg`），可与原生冰互相紊乱。引擎 `anomalyPool/helpers.ts` 已内置 `frostfire` 的分桶/持续时间/紊乱/乱流倍率，`DAMAGE_ELEMENT_LABELS` 已注册中文名“烈霜”。
- **模块位置**：`src/mechanics/agents/miyabi.ts`（完整模块，替换原 specPanelBuffs 薄包装）。
- **冰焰积蓄效率**：`transformSkillExecutions` 中 `anomalyBuildUpEfficiency += min(80, critRate) × coverage`——对带冰焰的敌人积累烈霜积蓄时，效率 = 暴击率×100%，上限 80%。**注意冰焰与霜灼互斥**：冰焰（30s）在霜灼·破触发时被消耗，目标进入霜灼状态（20s）期间雅无法附着冰焰。冰焰覆盖率 = 用户可调设置 `miyabi.iceFlameCoverage`（默认 0.5），`buildCharConfig` 读取后存入 `panel.miyabiIceFlameCoverage`，`transformSkillExecutions` 按覆盖率折算。
- **额外能力（同沐霜雪）**：队伍有支援/同阵营/异常角色时，霜月伤害+60%（走 `skillDmgBonus__basic` 限定基本攻击）；紊乱触发下次霜月架势无视 30% 冰抗（`enemyIceResReduction`）。
- **落霜资源**：`resources` 中 `miyabi_frost_fall`——紊乱×2 获取、上限 6；霜月架势三段消耗 6 落霜（最赚，默认用三段）。
- **霜月架势三段**：`1091029`，`buildExecutions` 按 `floor(落霜总量 / 6)` 生成执行次数，伤害 4282.8% 烈霜直伤。
- **霜灼·破**：`buildExecutions` 生成固定倍率 1500% 直伤执行（吃双爆不吃精通），次数由用户设置 `miyabi.frostburnBreakCount` / `miyabi.frostburnBreakRate` 控制（毕业终局战斗取最高倍率）。
- **C1**：每消耗 1 落霜，霜月无视 6% 防御（最多 6 层=36%），在 `transformSkillExecutions` 中按落霜总量折算。
- **C2**：暴击率+15%、入场+6 落霜。**C4**：霜灼·破伤害+30%。**C6**：极意霜月伤害+30%（`skillDmgBonus__basic`）。
- **风属性覆盖率**：队伍有风角色时，风化状态不被覆盖→霜灼状态无法触发→霜灼全队积蓄效率 buff 覆盖率为 0%（`applyPanel` 中 `miyabiHasWindTeammate` 标记控制）。

### 琉音（liuyin / 1481）

- **等效总量规则（用户确认）**：**转大次数 = floor(好评总量 / 90)**（好评满 90 开窗即可抱拳转大，60/90 分配在 `promoteFixpoint` 按连携窗口拆）；**抱拳次数（送客长按 1481009）= 转大次数 + 琉音终结技次数**（终结技送客诉→抱拳不转大，纯伤害）。整局总量结算，不按客诉单条上限 1 截断。
- **好评转大（60 替换 / 90 白送）**：60 转大 = 目标队友有连携窗口时消耗 60 好评把这次连携升级为终结技（**连携 -1、终结技 +1 替换**）；90 转大 = 无连携窗口时消耗 90 好评直接打出终结技（**终结技 +1 白送**）。60 次数默认按失衡次数、可调 `liuyin.hug60Count`，并受开窗次数（floor(好评/90)）与连携窗口数双重夹紧。倍率表 damage/daze/anomaly_buildup 全走目标队友执行计划自然调用。
- **连携次数公式**：`连携次数 = 每次失衡连携次数(chainCountPerStun) × 失衡次数`，资源池 `iterate` 已按此实现（`config.stunCount` 参数化）；被 60 转大替换的连携**真的没打**，最终 `chainCountTotal` 与执行计划都扣减。
- **循环收敛**：`失衡次数 ↔ 资源池（连携=每失衡连携×失衡次数）↔ 失衡池 ↔ 异常喧响奖励` 外层不动点（`calcOutput`，6 轮兜底；异常/特殊动作奖励计入终结技次数后，`终结技次数` 与 `异常奖励序列` 稳定也纳入收敛判据），每轮内层再做 `失衡次数 ↔ 好评转大` 不动点（8 轮兜底）；好评≥90 开窗次数有界，全部单调收敛。目标队友槽位可调 `liuyin.ultimateTargetSlot`（默认取上一位角色）。
- **三个强特（石头→剪刀→布）**：各耗 25，按 1→3 顺序连打（越靠后数值越高）。失衡次数×25 能量留给失衡内首个强特（石头），剩余非失衡按 1→3 连打。`buildExecutions` 生成三段执行，伤害池按 `stunCount` 拆失衡/非失衡易伤。**强特次数强制整数**（`cfg.exSpecialCountFloor`，不走柏妮思的小数期望值模型）。
- **抱拳（送客长按 1481009）**：次数 = 转大次数 + 琉音终结技次数（等效规则），造成物理伤害并触发上一位角色快速支援。**完整倍率行**（damage/daze/anomaly/喧响/动作时间）由 `buildCharConfig` 从倍率表读取、执行计划直接覆盖（`liuyinFarewell*` cfg 字段），不依赖回填。
- **核心被动·暴击转冲击**：初始暴击率超过 50% 时每超过 1% 冲击力 +2，最多 +100（100% 暴击封顶）。`applyPanel` 面板直加 `impact`。
- **额外能力·强特暴伤 +50%**：新增技能专属暴伤 `critDmg__exSpecial`（`core/buff.ts` `TARGETABLE_STATS` 扩展 + `core/damage.ts` 暴击乘区按 `skillDamageTarget` 定向读取），仅强化特殊技生效。
- **额外能力触发条件（声明式）**：`spec.additionalAbility` 声明 `teamConditions`（`specialty` 存在强攻/命破），引擎 `evalAdditionalAbility` 统一判定写入 `panel.additionalAbilityActive`（0/1），模块按标记开关——不再硬编码条件函数。通用机制（新增 `src/specs/teamCondition.ts` + spec 类型 `TeamConditionSpec`），后续角色填 JSON 即可。
- **额外能力·专属直伤**：石头/剪刀/布重击命中时按上一位队友特性追加伤害——强攻队友 320% 攻击力、命破队友 400% 贯穿力。走 `calcDirectDamage` 的 `basisValueOverride`（读队友面板），队友槽位可调 `liuyin.previousTeammateSlot`（默认自动取前一位）。
- **影画4·进场能量 +20**：走 `cfg.initialEnergyGift`。**影画4·好评如潮下攻击力 +500**：默认满覆盖（`liuyin.goodReviewAtkCoverage` 可调）。**影画1·好评如潮无视抗性 / 影画2·恶意投诉失衡易伤+伤害**：已在 `teammate-buffs.json`。
- **强化A（普通攻击：猜拳把戏 #1-#4）**：布（1481013）次数决定可打轮数，每轮 4 段各 push `count=rounds`（1481005-1481008，`damageMultiplierOverride`），占用平A时间——从 `basic_attack` 行 `totalTime` 扣减，平A时间不够按整轮截断。4 段秒均一致（damage≈326.5/s），与单条秒均行完全等效；4 段 push 让失衡/积蓄池按真实段调用（伤害池已支持秒均行，两种模型都进总伤）。
- **影画6·余音**：转大次数（60+90 抱拳之和）× 12 次 × 480% 物理直伤（视为强特），默认全打满（`liuyin.c6EchoMax` 可调）。**轴模式同样生效**（曾包在非轴强特拆分 `!isAxis` 块内导致失衡轴模式下 6 命提升率显示 0%，已移出独立生成）。
- **模块位置**：`src/mechanics/agents/liuyin.ts`。

## 最终面板（可验证性工具）

- **结果页「最终面板与乘区」卡片**（`src/components/FinalPanel.vue`，数据源 `computePanelPhases`，与计算引擎同源）：三角色 tab，每角色展示 局外→局内 全字段表 + 乘区数值汇总 + **局内生命构成来源明细**。
- **乘区按公式位置划分（不是所有带"增伤"字眼都归增伤区）**：
  - 直伤链：基础区（atk / 命破贯穿力 / 锋御防御力）→ 直伤增伤区（**仅** 通用 dmgBonus + 元素 + 招式 skillDmgBonus）→ 锐化增伤区（sharpDmgBonus，锋御独立，公式 3.5）→ 贯穿增伤区（penDmgBonus+sheerDmgBonus+元素贯穿，命破独立，公式 4）→ 防御 → 抗性 → 易伤 → 失衡 → 暴击。
  - 异常链：异常增伤（anomalyDmgBonus+windAnomalyDmgBonus）在异常公式区；异放增伤（anomalyReleaseDmgBonus）独立区；乱流增伤（turbulenceDamageBonus）；紊乱增伤（disorderDamageBonus）在紊乱结算区；异常暴击独立。
  - 属性表按上述分组（增伤区组只含直伤三类；锐化/贯穿/异常各自成组）。
- **局内生命构成**：列出每个提供局内生命的 buff 来源（角色自身/teammate-buffs/音擎/驱动盘/全局），含字段与数值（fixed 按**精炼等级**取 `modificationValues` 并 ×覆盖率；derived/formula 标注表达式），并给出公式 `局外 hp × (1+Σ局内生命%) + Σ局内生命固定 = 局内 hp`——用于核对"涌泉/专武的局内大生命到底进了多少"（如伊德海莉 3命→4命 时生命来源应多出「伊德海莉·影画四 +5%」一行；卢西娅专武 `zzz_wiki_1611` 5精炼显示 hpPct 24%）。
- **id 统一约定（2026-08 迁移）**：全库 id 一律纯数字字符串——音擎（如卢西娅专武 = `14145`，旧 `zzz_wiki_1611` 存 `legacyIds`）、驱动盘套装（如 `34200`，旧 `zzz_wiki_2121` 存 `legacyIds`）、`agent.teammateBuffId` 与 teammate-buffs 的 group id / buff id 前缀（旧 slug 如 `jane_doe`/`remielle` 已改数字）。`getWEngine`/`getDriveDiscSet` 按 `legacyIds` 兜底兼容旧 localStorage 配置；`remielle.q:{slot}` 等设置 key 保持原名（持久化兼容，不属 id 体系）。
- **用途**：调命座/装备后核对"某加成是否真的进了最终属性"；逐条 buff 全字段明细见「公式/字段」调试页。
- **实现**：`computePanel` 重构为 `computePanelPhases`（返回 `{ outOfCombat, inCombat }`）的薄包装，两阶段面板一次计算；生命来源由 FinalPanel 遍历 catalog combatBuffs / teammate-buffs（启用+命座达标）/ 音擎（职业匹配）/ 驱动盘 / 全局 buff 收集（stat ∈ hpPct/inCombatHpPct/hpFlat/inCombatHpFlat）。
