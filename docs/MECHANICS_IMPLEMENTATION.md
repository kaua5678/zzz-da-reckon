# 角色特殊机制理解与实现方法

> 给后续 AI 记录角色特殊机制时的统一思路，目标是减少来回确认、把机制落到可计算的数据和代码。

> **⚠️ 角色录入必读（AGENTS.md §0）**：任务是「录入新角色 / 补机制 / 核对口径」时，动手前必须读本文件中**该角色档案段**（`grep -n "角色名\|agentId"` 定位）。档案段记录该角色**已确认口径**与**未建模项**——不读 = 凭印象实现 = 必然踩坑。

> **档案段格式规则**：段首「**当前实现状态**」标注 `[已实现]` / `[部分实现]` / `[未建模]` + 实现位置（文件/测试）+ 核对日期。**没有状态行的段 = 尚未核对**——录入该角色时，先核对现状再补状态行，不要写「待核对」占位（占位=噪音+误导，等于没核对）。改完机制**同步更新状态行与口径**。

## 1. 理解机制的顺序

1. 先读 `passive`（核心被动 + 额外能力），确认机制主干：伤害形态、资源、状态、触发条件。
2. 再读 `skill` 描述，找到具体招式名和伤害段，和倍率表 moveId 对应。
3. 最后读 `talent`（命座），区分哪些是本体机制、哪些是命座增强。
4. 对每条机制问三个问题：
   - 来源：什么动作/事件产生它？
   - 消耗：什么动作/事件消耗它？
   - 收益：消耗后换来什么（伤害、状态、额外动作）？

## 2. 机制分类

- 资源（resource）：有存量、有获取、有消耗，例如洛克茜风能、克拉蕾锐能。
- 状态（state/stack）：叠加在敌人或自身上的层数，例如克拉蕾残痕（敌人 3 层）、风眼（场上对象）。
- 事件（event）：不占普通招式行、由动作触发的额外伤害，例如毁伤、风眼毁坏、小旋风秒伤。
- 转模（attribute conversion）：由某个属性阈值/步长换另一个属性，例如洛克茜初始防御 → 攻击/冲击。
- 覆盖率：没有专门说明时默认 100%（结果页有覆盖率调整接口）。

## 3. 落库路径

1. 机制描述先写进 `src/specs/agents/<id>.json` 的 `resources` / `events` / `attributeConversions` / `notes`。
2. 能在通用解释器表达的用 spec 数据；需要按动作轴计算的在 `src/mechanics/agents/<id>.ts` 实现并注册。
3. 可确认数值写进 `verifications`，变成 golden test。
4. 猜测机制先落库并标 `[猜测·高/中/低]`（标注格式见 `src/specs/template.json` 的 `_comment` 与 `scripts/validate-specs.mjs` 头注释），未确认的保持 `not_described_not_implemented` 或 `implemented_approximation`，在 notes 里写清缺口与待核对点。

## 3.1 事件 → 倍率表映射

倍率表里少部分行不是“一个招式对应一行”，而是被多个事件按关系复用。用事件来定义“实际招式调用哪一行倍率”：

- `executionKind: "execution"`：该事件会生成实际招式执行，进入伤害池。
- `carrierMoveId` + `multiplierRowId`：指定调用倍率表的哪一行（默认 `damage`）。
- `multiplierRatio`：复用时的缩放系数，例如风炮 = 起风倍率 × 0.3 + 风炮爆炸倍率。
- `countField`：次数由机制模块通过 `counts` 上下文传入，支持非内置 countSource。
- `overrides`：模块可对事件动态覆盖倍率（例如葬血强袭按消耗个人资源每点 +6.5%）。

实现位于 `src/specs/mechanics.ts` 的 `buildSpecEventExecutions`，洛克茜/克拉蕾模块已用它生成风炮、风眼、毁伤等实际招式执行。
