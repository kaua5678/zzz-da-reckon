## 2. 因子隔离实测（三支代表队，逐因子开关）

| 队 | A 旧默认+旧buff | B 只清 buff | C +daze | D +异常系数 | E +def/秽盾 | F 新默认 | 总变化 |
|---|---|---|---|---|---|---|---|

逐因子贡献（以队 1041-1161-1311 为例）：
- **清默认 buff**（A→B）−20.3%：那 20% 攻击 + 15% 增伤是**某期危局的环境**，木桩没有。
- **改 daze**（B→C）0%（该队失衡次数未跨台阶；跨台阶的队在 C 步有 −6.9%，见 1461 队）。
- **改异常系数 1.1→1 / 1→1.25**（C→D）−1.2%：`bossAnomalyCoeff` 那个 +10% 是危局属性浸染，木桩没有；同时 `anomalyCoeff` 1→1.25 抬高积蓄阈值（更难触发异常）。
- **改防御 953→952.8 + 秽盾 1→0**（D→E）−1.0%：破盾奖励 60 能量×1 次消失。
- **改血量**（E→F）**0%**：血量不是伤害输入（只影响「伤害/血量%」派生）。

## 7. 判据与产品默认解耦（方案 1 落地，2026-10-27）

用户裁决：「那就做 1 吧。这测试也是够麻烦的，每次开发都畏手畏脚。」

### 问题不是默认值，是**判据曾经依赖产品默认**

67 条判据变红的根因：它们从未 `setEnemy`，一直吃 store 默认。A/B 实测（HEAD 版 config.ts = 10 条红，换默认后 77 条）
⇒ 那 67 条不是「算错了」，是「隐含前提被产品默认偷偷改写了」。**这才是「每次开发都畏手畏脚」的根因**：
改一个默认可信手翻掉几十条无关判据，而它们测的根本不是默认值。

### 修法：夹具自带一把固定的尺子（`src/test/harness.ts`）

| 导出 | 用途 |
|---|---|
| `BASELINE_ENEMY` / `BASELINE_GLOBAL_BUFFS` | **判据基线**，逐字冻结在 2026-10-27 之前的产品默认（205,970,837 血 / 15,486 失衡 / 防御 953 / 危局 1.1 / 秽盾 1 + 两条危局buff）。**不跟随任何产品默认变化** |
| `TRAINING_DUMMY_ENEMY` | 木桩的判据侧镜像，只给「就是要测默认值」的判据用；有判据断言它与 `defaultEnemy` 逐字段一致（防两处漂） |
| `setupHarness(team, { fixtures })` | `fixtures`：**缺省 `'baseline'`**（与产品默认解耦）/ `'product'`（保留产品默认）/ 对象（精确指定） |
| `newPiniaWithFixtures()` | 给那些「在 beforeEach 里 `newPinia()` 后自己塞 team」的老判据用（般岳 / 仪玄冒烟等 2 处已迁） |
| `newPinia()` | **保持原义**（不套夹具 / 保留产品默认）——要测产品默认的判据用它 |

改 `defaultEnemy` / `defaultGlobalBuffs` ⇒ 只红**真正测默认值**的那几条（本轮 = `trainingDummyDefault` 11 条 + 镜面一致性），
