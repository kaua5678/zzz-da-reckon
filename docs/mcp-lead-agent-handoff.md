## 7. 收到工人报告后，你必须独立做什么

1. **先看真实 diff 与归属**：是否超白名单、带入他人 WIP、改动依赖/阈值/生成产物。
2. **核对反例因果**：失败必须是预期问题，而不是环境或测试夹具错误；关键结论至少亲自重放一条正控、一条负控。
3. **核对真实出口**：例如缓存问题要测 computed 消费者，不能只测直读 getter；动作问题不能只证明元素被找到；文档状态不能只证明文本含有 expect。
4. **核对产物时效**：报告、截图和日志必须属于这次运行及这份源码，不能拿旧成功文件充数。
5. **核对未证明的部分**：接受明确的 unknown/blocked，不接受把猜测写成“已实现”。
6. **核对既有裁决**：不重做已结案事项，不把被证伪的旧方案重新包装立项。
7. 给出自己的 `accept / revise / blocked / no-go` 结论与理由。不要只复述工人的“全部通过”。

如果你必须亲自修改工人代码，先接管对应文件，避免同时写入；然后按真实最终 diff 重新验证，不能仍引用修改前的通过结果。
