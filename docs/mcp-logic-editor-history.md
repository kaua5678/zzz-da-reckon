# MCP 开发：逻辑编辑器可逆试改

## 分析

上一轮已提交为 `078c5c1`，解决了输入/持久化安全，但误删、误改、导入替换和恢复默认仍不可撤回。规则编辑适合低成本试验：保留当前会话的有效配置历史，比要求用户每次手动导出备份更直接。

现有对象 JSON 文本缓存按可编辑的 `id` 存在普通对象里；同 id 的历史快照会复用旧文本，`__proto__` 还会命中对象原型。因此历史恢复必须同时解决编辑文本的身份问题，而不是只换 store 数组。

## 方案与验收判据

1. 仅对完整通过 `parseLogicEditorState` 的配置建快照，保留当前状态加最多 50 步；不增加存储 key、持久化历史或第三方依赖。刷新页面从最新缓存开始，历史清空。
2. 同一 Vue 更新批次的有效字段修改归为一步；保存和 watcher 回声不重复记步。导入/恢复默认先记录尚未 flush 的有效旧草稿，避免吞掉前一步。
3. 撤销/重做同时恢复表单、有效倍率和缓存；存储失败仍可在内存导航，并保留上一轮的失败提示。接口返回值代表历史操作是否执行，不冒充持久化成功。
4. 无效数值不进入历史；撤销无效草稿只恢复最近有效配置，不额外后退，也不破坏已有重做分支。新的有效编辑截断重做；被拒绝的导入和相同配置不截断。
5. 历史快照不能持有活草稿引用；上限截断、连续撤销重做、导入/重置/增删、旧对象引用修改都要有回归。
6. 页面提供撤销/重做按钮与会话步数。Ctrl/Cmd+Z、Ctrl/Cmd+Shift+Z、Ctrl+Y 仅处理逻辑页内的非输入控件事件；输入框、textarea、contenteditable、IME 和已处理事件保留原生行为。
7. 对象 JSON 草稿改用对象身份的 WeakMap，历史替换自然取得新文本；改 id 不丢草稿，特殊字符串 id 不命中原型。
8. 有效倍率快照通过 shallowRef 通知 `getRowValue` 的 computed 消费者；只比较实际参与匹配/乘法的字段，避免备注修改或重复保存触发昂贵重算。求值顺序与倍率公式保持不变。

复核发现：原融合模块用普通模块变量，直读 getter 测试看不见 Vue 缓存不失效。追加真实 `getRowValue` 的 computed 反例，实测倍率 2→3 后仍返回 200 而非 300；直接 setter 的输入引用还可绕过快照隔离。三条反例先红，再修正发布边界；不以复用活草稿恢复响应性。
