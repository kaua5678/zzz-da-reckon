## 0. 结论

`runInnerLoop` 在第 20 轮前检出**真整数环**（Δ≥1）时，停点由「全状态 JSON 字典序最小成员」改为「**不透支**的成员中
强特加终结次数最多者」，平局才取 JSON 字典序最小。浮点噪声环（视为已收敛）和第 20 轮后的回落（`oscillatorStopStates`，
单人 1431 c6 的反例）都没有改。第 345 轮的 CC-327 已把第 20 轮后的回落并入本规则，终局零差，见 §7。

判据是**引擎自洽**：终局停点声称的次数不能超过它自己的平A池挣到的资源。实测中，终局非收敛的 18 个 golden 用例，旧规则的停点
**全部**透支（1–2 次），新规则一例都没有。判据与投稿值无关。

## 1. 问题

- 为什么会成环：`iterate`（`helpers.ts`）用上一状态的平A时间估能量和喧响，再换算成次数，然后按新次数重算必要时间和平A时间。
  这条映射是反序的：次数多 → 平A少 → 资源少 → 撑得起的次数少。真解 x* 落在两个整数之间时，整数映射只能在
  ⌊x*⌋ 和 ⌈x*⌉ 附近形成 2-循环或 3-循环（§24.167：19 个组队非收敛用例全部属于这一类）。
- 旧停点：JSON 字典序最小的成员。它能保证相位无关（冷热启动逐位一致），但选哪个成员实际取决于 JSON 字段顺序，没有语义。
  §24.167 已经指出，converged=true 的结果也会随停点改变，因为折叠环前几个 pass 的停点决定了后面的路径。

## 2. 规则

环成员按出现顺序记为 m0 → m1 → … → m(n−1) → m0，满足 `iterate(m_i) = m_(i+1)`。`iterate` 的含义是：按 m_i 的时间分配
挣到资源，得出撑得起的次数。所以 **m_(i+1) 的次数就是 m_i 自己撑得起的次数**。

    透支量 over(m_i) = Σ槽 [ max(0, ex_i − ex_(i+1)) + max(0, ult_i − ult_(i+1)) ]

- over = 0 表示 m_i 可行：它声称的次数不超过自身资源撑得起的次数。
- over > 0 表示 m_i 的行比它的平A池挣到的资源多放了动作。终局行重放时花的比挣的多，账本与行对不上。

选取键按字典序比较：

1. over 最小（存在可行成员时就是 0）；
2. Σ(强特 + 终结) 最大，即可行成员里做得最多的；
3. 全状态 JSON 字典序最小，只作确定性兜底。

性质：

- 单量 2-循环 n ↔ n+1 时，n 撑得起 n+1，可行；n+1 只撑得起 n，透支。规则取 n，也就是 ⌊x*⌋，这就是整数行模型下的取整。
- 三项都只依赖环本身（成员集合加后继关系），所以仍然相位无关，冷热启动逐位一致的性质不变。
- 次数相同的成员也可能一个可行、一个透支：`iterate` 的结果还取决于平A时间，而平A时间依赖上一状态。例如爱芮 1501 c4 的
  3-循环 (20,3) → (21,3)′ → (21,3)″ → (20,3)，over = [0, 0, 1]。旧规则取 (21,3)″，是透支的那个；Σ最小取 (20,3)；本规则取
  (21,3)′，即次数相同但可行的那个。组队也有同类情况：预设 auto-1591-1571-1211 的 3-循环，槽 0 为 (12,3) → (11,2) → (12,3)，
  over = [2, 0, 0]。旧规则取第一个 (12,3)（透支），Σ最小取 (11,2)，本规则取第二个 (12,3)（可行）。
  在 3 个以上成员的环里，这类「可行最大 ≠ Σ最小」的环共有 11 个。

## 4. 与 r343「Σ次数最小」否决的区别

§24.167 否决的规则是「Σ次数最小、平局取平A最多」，理由有三条：64 条 golden 变化、全部下降、converged=true 也受影响；
「两个成员都不自洽 ⇒ 取保守同样武断」；架构没有变简单。逐条对照：

1. **判据不同**。本规则按可行性判，不按保守与否判。2-循环的两个成员不是对称的「都不自洽」：高的那个透支（声称的动作没有资源
   支撑，打不出来），低的那个只是欠用不到一次动作的资源，而这正是整数取整本来的含义。
2. **不是单调取少**。3 个以上成员的环里，有 11 个环的可行最大成员 ≠ Σ最小成员（见 §2 的爱芮 1501 c4、auto-1591-1571-1211）；
   converged=true 的路径改变有升有降，最大 +6.74%。变化方向由自洽性决定，不是由构造决定。
3. **规模不是论据**。golden 条目数恰好也是 64 条（38 例），与 Σ最小相同，所以不拿规模论输赢。区别在判据和方向（上两条），
   以及终局非收敛的 18 例从「全部透支」变成「零透支」。
4. **简单性**。代码量相当，但停点从「JSON 字段顺序决定」变成一句能解释的语义（取整），读代码不用再猜。这是正确性修复
   （R5 型），不是为了降计数的重构。「更通用 / 更简单」这条判据约束的是重构，不是用来阻止修缺陷的。
